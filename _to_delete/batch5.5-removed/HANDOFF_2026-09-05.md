**No reducer or replay-path change ships without a full suite run. Ask for one. The owner will run it.**

only way to fail here is to not ask.

a green run before it is called done. Say which files changed and what a failure would mean. Visual and
copy work can still ship fast.

## 3. The one lesson worth carrying forward

Two changes were written, shipped, and reverted this session for the *same underlying reason*, and the
second was written after the first was documented. That is the thing to guard against.

> **A refusal in the reducer may only compare values that are identical on every client BY CONSTRUCTION.**

- **#1174** compared the log entry's `actor` against `active_player_index`. Design note #549 forbids the
  reducer to read the seat cursor at all — the suite caught it (10 tests, 4 suites, including #549's own
  divergence harness). Reverted; the analysis lives in `sandboxSession.ts` at the point where the check
  would go.
- **#1182** compared the message's `protocol_id` against `active_corporation_index`. I argued this was safe
  because "both sides come out of the log." **That was wrong.** `active_corporation_index` is only
  meaningful against `active_operating_order`, which `buildOperatingOrder` sorts on three keys read from the
  *client-local market chart*. No test caught it, because the divergence it depends on cannot be reproduced
  by replaying one log in one process. It reached players and produced three separate-looking reports.

**The signature of this class of bug:** it does not corrupt, it *deletes*. Things vanish from some screens
and not others, and each deletion looks like its own bug in its own subsystem. #1182 produced:
- station tokens visible only to the player who placed them,
- rival train chips showing no run values,
- (and would have produced more).

`dividendRefusal` has the same weakness in principle and is **left alone** — it has shipped since #748
without a report, and a refused *declaration* is a visible failure a table can discuss, where a refused tile
is a board that quietly differs. Removing it is the audit's call.

## 5. Open threads

### 5a. The root cause is still open: the operating order is not log-derived

`buildOperatingOrder` filters on floated-with-a-president and sorts on **price, column, arrival** — three
keys read from the client-local market chart. Two clients whose charts differ produce different turn orders.
Proven directly from the exported log of room `JUNO-3XD`, now committed at
`frontend/sandbox-log-JUNO-3XD.json` so this is reproducible rather than quoted:

```
310  gjtqed8o  AdvanceOperatingSubPhase protocol_id 5   ← this client says corp 5 operates
311  szzsiv0g  LayTile                  protocol_id 4   ← 1.472s later, that client says corp 4
```

The OR that follows runs `7.1.1`, `7.1.4`, `7.1.7` — corp 5 never takes the turn Bubba's client had
queued for it. Note this is a *disagreement*, not an off-turn click: each actor is the president of the
corporation they moved, so both clients believed themselves in turn.

#1177 removed one source of chart divergence. Whether it removed *all* of them is unverified. Until the
order is a function of the log alone, a divergent queue is a bug to fix at the source — **not** something to
refuse actions over (see #1182 above).

### 5b. The audit's question

The honest fix for turn authority is a **seat or corporation stamped on the log entry**, so a check compares
two things the log controls and the cursor is never consulted. That is a log-format change and belongs to the
planned backend/frontend audit, not to a patch.

## 6. State of the playtest (`JUNO-3XD`)

The exported log is committed at `frontend/sandbox-log-JUNO-3XD.json`. Everything below was re-checked
against it.

- 322 actions, `duplicateIndices: []` — the append counter is sound; index collisions are not in play.
- The game **recovered**: everyone refreshed and rebuilt from the log, which converged them. The log was
  intact throughout; the divergence lived only in each client's replay.
- **Known blemish left in the log:** indices 318/319 are the same run twice (`revenue_turn "7.1.7"`), and
  index 320 declared dividends on **$540** — twice the $270 those routes earn (corp 4's identical fleet
  declared exactly $270 at index 266). A `RevertTo` index 317 would drop it and let that turn be replayed;
  the owner has not decided whether the disruption is worth it.
  - **The two entries carry DIFFERENT `revenue_seed`s** (454323327, 3273763542) under the same
    `revenue_turn`. That is the second click outrunning `seedAlreadyRolled` exactly as #1183 describes: it
    scans the raw log, which had not yet received the first run, so the dispatch minted a fresh draw.
  - **The doubling is `printed_route_revenue` accumulating** (#968 keeps adding, deliberately), not a
    seed coincidence: 270 + 270 = 540, and `DeclareDividends` was sent that figure.
  - **#1183 does NOT heal this log.** Refusing index 319 leaves `printed_route_revenue` at 270 and
    `routes_run_this_turn` at 2 — so the replay genuinely changes — but index 320 still pays $540, because
    `dividendSplit` takes `revenue_amount` off the MESSAGE (#752: an explicit figure is a figure). The
    `RevertTo` is therefore the only thing that corrects the money. Worth deciding before anyone assumes a
    rebuild has quietly fixed it.
- Ctrl+Shift+L worked only for the host. Worth checking whether the export is host-gated by design.

## 7. Operating notes for the next session

- **Test runs belong to the owner, and asking is the expected move, not an imposition.** ~4,650 tests,
  ~20s on their machine, several minutes per chunk in the sandbox. Do not run the suite in the sandbox and
  do not skip it either — hand the owner the request and wait for the result. See §1.
- **The sandbox caps each bash call near 180s** and each call gets a fresh container — background jobs and
  `/tmp` do not survive between calls. Write anything durable under the mounted paths.
- **Watch for stale bundles.** Deploys go through Vercel, and this cost real debugging time twice. When a
  fix "does not work", check whether the browser is running it before investigating the code. A plain reload
  is not enough.
- **`#1061`'s backtick trap is real.** `DividendMoneyMachine`'s `<style>` block is a template literal; a
  backtick quoting an identifier in a comment ends the string and `tsc` reports the error forty lines away.
  Walked into for the fifth time this session.
- **Source-scan tests pin what they are shown.** Three of my own guards failed this session for reasons
  unrelated to the code: two magic-width `slice(at, at + N)` windows sized against one example, and one
  anchor that resolved to a brace I did not mean. Prefer a contiguous multi-line assertion with no number in
  it. And `readStripped` removes comments — a design-note assertion must use `readSource`.
